🛡️ Core Architectural Invariants & Development Contracts

1. Multi-Tenant Scoping (school_id): Every table deriving from TenantBase carries an indexed school_id foreign key pointing to schools.id. Only schools (tenant anchor) and alembic_version (system engine) lack it.
2. The Enrolment Invariant: A student joins a class for an academic session via enrolments. All year-scoped facts (marks, attendance, fees, bus seat) hang off enrolment_id, never student_id directly.
3. Contract 3 Compliance Auditing: Destructive operations (status changes, voids, reversals, marks overrides) mandate a user-typed reason and commit immutable entries to audit_log with IP and user ID.
4. Financial Immutability: Money rows in fee_invoices, fee_invoice_lines, and fee_payments are never updated in-place. Cancellations create void flags and reversals post audited contra-allocations.
5. Contract 1 (Canonical Screen Registry): Every web screen is declared once in web/src/screens.ts. Navbars, routes, and RBAC gates derive strictly from this single source of truth.
6. "UNUSED FOR NOW" Designation: 28 tables are currently unpopulated in seed data. Each table is fully implemented with SQLAlchemy models and working endpoints, reserved for operational counter workflows or planned roadmap modules.
